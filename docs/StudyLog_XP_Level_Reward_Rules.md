# StudyLog Study XP · 레벨 · 보상 규칙

**목적:** 현재 코드에 이미 구현되어 있는 진행/보상 규칙을 한 문서에 모아 정리한다. 새 규칙을 만들지 않으며, 아래 내용은 전부 실제 소스 코드에서 그대로 옮긴 것이다 — 각 항목에 근거 파일 경로를 함께 남긴다.

---

## 1. 단일 진행 체계 (Single Source of Truth)

```
공부 활동(타이머 세션) → Study XP → 레벨 → 방 성장 / 달성 가능한 보상
스터디 포인트(별도) → 코스튬 구매
```

- **Study XP**는 오직 실제 타이머 세션에서만 발생한다 (`earn_study` 트랜잭션). 광고 보너스, 연속 출석 보너스는 Study XP에 절대 포함되지 않는다 — `pointsMath.ts`의 `computeStudyXpTotal`이 `earn_study` 타입만 합산한다.
- 코스튬 구매(포인트 소비)는 Study XP·레벨에 영향을 주지 않는다 (`spend` 트랜잭션은 `computeBalance`에서만 차감되고 `computeStudyXpTotal`에는 반영되지 않음).
- 광고는 스터디 포인트(`earn_other`)만 지급하며 Study XP를 지급하는 경로가 코드 어디에도 없다.

근거: `src/store/pointsMath.ts`, `src/store/pointsStore.ts`

---

## 2. Study XP 공식

```
raw = floor(세션 durationSec / 600) * 1   // 10분당 1 포인트, 초 단위 절삭
awardable = max(0, min(raw, 60 - 오늘 이미 적립한 Study XP))
```

- 10분 미만 세션은 Study XP를 얻지 못한다 (버림 연산).
- 하루 적립 상한(§3)을 넘는 만큼은 잘려서 지급된다.

근거: `src/store/pointsStore.ts` `earnFromStudySession`, `POINTS_PER_10_MIN = 1`

---

## 3. 일일 Study XP 상한

```
DAILY_STUDY_POINT_CAP = 60  // 하루 최대 60 Study XP (= 최대 10시간 분량)
```

10시간을 넘는 공부 자체는 막지 않지만, 그 이상은 Study XP로 적립되지 않는다 — 무제한 연속 공부를 보상하지 않기 위한 장치.

근거: `src/store/pointsStore.ts`

## 4. 레벨 곡선

RPG형 파워 커브. 레벨 자체는 저장되지 않고 항상 누적 Study XP의 순수 함수로 계산된다(어긋나거나 조작될 여지가 없음).

```
레벨 L을 깨는 데 필요한 EXP = round(20 * L^1.5)
```

| 레벨 | 해당 레벨을 깨는 데 필요한 EXP (누적 아님, 그 레벨 구간에서 필요한 양) |
|---|---|
| 1 | 20 |
| 2 | 57 |
| 5 | 224 |
| 10 | 632 |

누적 Study XP가 이 값들의 합을 넘어설 때마다 레벨이 오른다.

근거: `src/character/engine/expLevel.ts` (`EXP_BASE=20`, `EXP_EXPONENT=1.5`)

## 5. 방 성장 임계값 (레벨 연동)

캐릭터 자체가 아니라 "방"이 레벨에 따라 누적 성장한다 — 한 번 해금된 요소는 사라지지 않는다.

| 레벨 | 해금 |
|---|---|
| 1 | 시작의 책상 |
| 10 | 식물 |
| 20 | 고양이 |
| 30 | 의자 업그레이드 |
| 40 | 책 증가 |
| 50 | 듀얼 모니터 |
| 70 | 창문과 커튼 |
| 100 | Premium Study Room |

근거: `src/character/room/growthStages.ts`

## 6. 연속 출석(스트릭) 정의 및 타임존 동작

- 스트릭은 "**하루에 한 번이라도 Study XP를 적립할 만큼(10분 이상) 공부한 날**"의 연속 여부로 계산된다 — `earnFromStudySession`이 호출될 때마다 오늘 날짜(`todayKey()`)와 `lastStudyDate`를 비교한다.
- 오늘 날짜가 "어제"였다면 `streakCount + 1`, 그렇지 않고 오늘 처음이면 `streakCount = 1`로 리셋된다.
- **타임존 동작:** `todayKey()`는 `Date.getFullYear()/getMonth()/getDate()`를 사용한다 — 즉 **서버 시간이나 UTC가 아니라 기기(브라우저)의 로컬 자정 기준**으로 날짜가 바뀐다. 사용자가 기기 시간대를 바꾸면 스트릭 계산에 영향을 줄 수 있다는 뜻이며, 이는 알려진 한계로 문서화만 하고 이번 단계에서 서버 시간 동기화 같은 구조 변경은 하지 않는다(§9 "실제 데이터가 없는 보상을 만들지 마"와 별개로, 기존 안정 로직을 불필요하게 바꾸지 않기 위함).
- 스트릭 보너스(스터디 포인트, Study XP 아님)는 `STREAK_MILESTONES`(3/7/14/30/100일)에서 지급되며 `milestonesAwarded` 배열로 같은 마일스톤이 중복 지급되지 않도록 막는다(§8 참고).

근거: `src/store/pointsStore.ts`, `src/utils/time.ts`

## 7. 달성 배지(업적) 조건

배지는 저장되지 않고 매번 실제 데이터로부터 다시 계산된다 — "잠긴 가짜 배지" 목록이 없다.

| 배지 | 조건 |
|---|---|
| 첫 기록 | 세션이 하나라도 있음 |
| 목표 달성 | 오늘 등록된 목표를 달성함 |
| 7일 연속 | 스트릭 ≥ 7일 |
| 30일 연속 | 스트릭 ≥ 30일 |
| 30시간 | 누적 공부시간 ≥ 30시간 |
| 100시간 | 누적 공부시간 ≥ 100시간 |

근거: `src/utils/achievements.ts`

## 8. 코스튬 보상 조건 및 중복 처리

- 코스튬(헤어/의상/액세서리/배경)은 전부 **상점에서 스터디 포인트 또는 캐시로 직접 구매**하는 방식이다 — 레벨업이나 업적 달성으로 자동 지급되는 코스튬은 없다. 즉 "실제 데이터 없는 보상을 만들지 마"는 이번 단계에서 자동-지급형 코스튬 보상을 새로 만들지 않는 것으로 지켜졌다.
- 중복 지급이 실제로 방지되는 곳은 **스트릭 마일스톤 보너스**뿐이다: `milestonesAwarded: number[]`에 이미 지급한 마일스톤을 기록해, 같은 스트릭 구간에서 두 번 지급되지 않는다.
- 구매한 코스튬은 `equippedAssetIds`로 관리되며, 이미 소유한 아이템을 다시 "구매"하는 UI 경로 자체가 없다(상점은 미보유 아이템만 "구매하기"로 표시).

근거: `src/store/pointsStore.ts`, `src/store/shopStore.ts`

## 9. 안전한 공부 보호 장치 / 어뷰징 방지 가정

실제로 구현되어 있는 것만 나열한다(과장하지 않음):

- **일일 상한(§3):** 하루 60 Study XP(10시간 분량)로 적립이 멈춘다 — 무제한 연속 공부를 보상하지 않는다.
- **자리 비움(away) 감지:** 화면이 5초 이상 숨겨지면(`document.hidden`) 타이머가 자동 일시정지되고, 자리 비운 시간은 `elapsedSec`에 포함되지 않으므로 Study XP로도 환산되지 않는다. 5초 미만의 짧은 전환(예: 알림 확인)은 "짧은 복귀"로 취급해 타이머를 그대로 이어간다.
- **최소 세션 길이:** 10분 미만 세션은 Study XP가 0이므로, 초 단위로 시작/정지를 반복해 포인트를 긁어모으는 방식은 애초에 보상이 없다.
- **가정의 한계:** 위 장치들은 전부 클라이언트(브라우저) 로컬 로직이다. 기기 시간 조작이나 로컬스토리지 직접 수정 같은 클라이언트 우회는 막지 못한다 — 서버 검증이 없는 현재 구조의 알려진 한계로만 문서화한다.

근거: `src/store/pointsStore.ts`, `src/hooks/useAwayDetection.ts`

### 건강한 공부 규칙 (PRD §21 방향성 — 현재 상태 대비)

PRD는 "위험한 연속 공부 시간을 보상하지 말고, 일관성·사용자가 정한 목표·완료된 집중 세션·건강한 휴식 후 복귀·주간 진행을 우선 보상하라"고 제안한다. 현재 구현과 비교하면:

- ✅ 이미 반영됨: 일일 상한(무제한 연속 공부 비보상), 스트릭 보너스(일관성 보상), 목표 배지(사용자가 정한 목표 보상).
- ⚠️ 아직 반영되지 않음: "건강한 휴식 후 복귀"나 "주간 진행"에 대한 별도 보상 로직은 없다 — 현재 Study XP는 여전히 세션 길이에 비례해서 지급된다(10분 단위).
- 이번 단계에서는 기존 안정적인 타이머/포인트 로직을 불필요하게 바꾸지 말라는 제약에 따라 **공식 자체는 변경하지 않고, 이 차이만 문서로 남긴다.** 실제로 로직을 바꾸려면 별도 승인과 함께 진행해야 한다.

## 10. 보상 이벤트 계약 (PRD §22) — 보류

PRD는 화면마다 보상을 각자 추론하지 말고 하나의 결정론적 `StudyRewardResult` 이벤트 구조를 제안하지만, "기존 안정적인 타이머 로직을 재작성하지 않고 적용 가능할 때만" 도입하라고 명시한다.

현재 `stop()` → `logSession()` → `earnFromStudySession()`으로 이어지는 경로는 이미 안정적으로 동작하며, 이번 단계에서 발견된 실제 버그(캐릭터 얼굴 가림, 스터디룸 성별 동기화 등)와 무관하다. 어댑터 계층을 지금 추가하면 실제 필요 없이 타이머 경로를 건드리는 위험만 생기므로, **이번 단계에서는 도입하지 않고 보류한다.** 향후 화면 간 보상 표시가 실제로 불일치하는 문제가 발견되면, `logSession()`을 감싸는 별도 어댑터 함수로 `StudyRewardResult` 형태를 계산해 반환하되 기존 `earnFromStudySession`/`sessions` 갱신 로직 자체는 그대로 두는 방식을 권장한다.
